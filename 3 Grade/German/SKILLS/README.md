# SKILLS — инструкции для агентов

Эта папка содержит **skills** — готовые наборы инструкций для OpenCode или любого другого ИИ-агента. Skill нужен не для хранения обычных заметок, а для того, чтобы агент мог стабильно выполнять повторяющуюся задачу по понятным правилам: генерировать упражнения, проверять ответы, оформлять материалы, работать с определённым форматом данных и т. д.

Без skill агент каждый раз сам решает, как подойти к задаче. С хорошим skill он получает роль, цель, ограничения, алгоритм работы и критерии проверки. Поэтому результат получается более точным, единообразным и пригодным для использования без постоянных уточнений.

## Для чего нужны skills

Skills особенно полезны, когда задача:
- повторяется регулярно;
- имеет чёткие правила и исключения;
- требует определённого формата результата;
- легко испортить небольшой, но важной ошибкой;
- должна иметь одинаковое качество вне зависимости от запроса;
- требует самопроверки перед ответом.

Примеры возможных задач: создание учебных заданий, проверка грамматики, подготовка карточек, разбор текстов, генерация тестов, работа с таблицами, написание кода по правилам проекта, оформление конспектов или проверка готовых решений.

## Как агент использует skill
Когда запрос пользователя подходит под тему skill, агент читает инструкцию и действует по ней. В нормальном skill заранее описано:
1. **Что нужно сделать** — конечный результат и цель.
2. **Какие данные ожидать** — тема, уровень, количество заданий, режим работы и другие параметры.
3. **Как выполнять задачу** — правила, порядок шагов и допустимые варианты.
4. **Чего нельзя делать** — ошибки, нежелательные упрощения, ограничения.
5. **Как выглядит ответ** — шаблон, Markdown-формат, наличие ответов, объяснений и т. п.
6. **Как проверить себя** — список условий, которые агент обязан сверить перед выдачей результата.

Если часть параметров не указана пользователем, skill должен либо выбрать разумные значения по умолчанию, либо коротко уточнить только то, без чего нельзя выполнить задачу.

## Как создавать новый skill

Для каждой отдельной задачи создавай отдельную папку с понятным названием:

```text
SKILLS/
└── название-навыка/
    └── SKILL.md
```

Например, название лучше писать коротко, строчными буквами и через дефис: `text-analyzer`, `vocabulary-trainer`, `exercise-checker`.

Файл `SKILL.md` — главная инструкция для агента. В начале желательно указать метаданные:

```md
---
name: short-skill-name
description: Коротко: какую задачу выполняет skill и когда его нужно использовать.
---
```

После этого добавь саму инструкцию. Универсальный каркас:

```md
# Роль и цель

Кто этот агент и какой результат он должен получить.

# Входные данные

Что пользователь может передать и какие значения используются по умолчанию.

# Правила выполнения

Точные правила, алгоритм, допустимые и недопустимые варианты.

# Формат результата

Шаблон ответа, язык, структура, примеры оформления.

# Проверка перед отправкой

Список ошибок, которые нужно исключить.

# Режимы работы

Например: практика, проверка, объяснение, экзамен, интерактивный режим.
```

Не все разделы обязательны, но чем важнее и сложнее задача, тем полезнее явно их прописать.

## Принципы хорошего skill

- **Одна основная задача на один skill.** Не смешивай в одной инструкции десяток несвязанных обязанностей.
- **Пиши конкретно.** Вместо «делай качественно» укажи, что именно считать качеством.
- **Добавляй примеры.** Пример входа и правильного выхода снижает риск неправильного понимания.
- **Фиксируй ограничения.** Если что-то нельзя выдумывать, пропускать или менять — скажи это прямо.
- **Определяй формат.** Укажи порядок блоков, язык, разметку, наличие ключей или объяснений.
- **Продумывай крайние случаи.** Что делать при неполных данных, неоднозначном запросе или невозможной задаче.
- **Добавляй проверку.** Особенно для фактов, вычислений, языка, кода, дат и форматов.
- **Не перегружай.** Skill должен помогать агенту действовать, а не превращаться в бесполезный огромный свод правил.

## Что стоит включать в правила

Хорошие правила можно формулировать проверяемо:

| Слишком расплывчато | Лучше |
| --- | --- |
| «Делай интересные задания» | «В наборе не повторяй один и тот же тип задания больше двух раз». |
| «Проверяй ответ» | «Перед отправкой проверь орфографию, формат и соответствие всем условиям запроса». |
| «Используй простой язык» | «Объясняй на уровне ученика; незнакомые термины сразу определяй». |
| «Дай примеры» | «Для каждого нового правила приведи один корректный и один типичный ошибочный пример». |

Чёткие условия важнее красивых общих фраз: агенту должно быть понятно, как проверить выполнение каждого пункта.

## Тестирование skill

После создания или изменения skill проверь его несколькими разными запросами:

1. Обычный запрос с полными данными.
2. Короткий и расплывчатый запрос.
3. Запрос с необычным или сложным случаем.
4. Запрос на другой режим работы, если режимы предусмотрены.
5. Запрос с намеренно неверными входными данными.

Проверь, что агент:

- выбрал именно этот skill;
- не пропустил важные правила;
- не добавил запрещённого или выдуманного;
- выдал результат в нужной структуре;
- выполнил финальную самопроверку.

Если одна и та же ошибка появляется снова, не надейся, что агент «догадается»: добавь в skill чёткое правило, пример или пункт проверки.

## Поддержка

Skills — живые инструкции. Их стоит обновлять, когда меняются требования, находятся типичные ошибки или появляется более удобный формат результата. Изменяй skill после реальных примеров использования: так инструкции будут становиться короче, точнее и полезнее.

Главный принцип: **skill должен позволять агенту спокойно и предсказуемо генерировать именно то, что нужно пользователю, даже без длинных пояснений в каждом новом запросе.**
